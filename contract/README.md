# The frozen API contract

Phase 1 of the Web-client migration — see
[`../docs/frontend-platform-decision.md`](../docs/frontend-platform-decision.md).

| File | What | Generated by |
|---|---|---|
`openapi.json` | The full OpenAPI 3.1 schema of the live backend — 109 paths, 122 operations, 104 authenticated | `python scripts/export_openapi.py` |
`api-types.ts` | TypeScript types generated from that schema | `npx --yes openapi-typescript@latest contract/openapi.json -o contract/api-types.ts` |

## Why these files are committed

They are the **contract**, and a contract that is generated at build time moves
silently under whoever is writing against it. This project has already paid for
that once: 46 frontend calls target routes that never existed, and nothing
noticed until an audit was run by hand.

Committing the schema makes an API change **a diff in review**, before a client
is written against it. Once the React client imports these types, a call to a
route that does not exist becomes a **compile error** rather than a runtime 404
— which is the structural fix for that entire bug class.

## Regenerating

After any change to a route, a request model, or an auth dependency:

```bash
python scripts/export_openapi.py
npx --yes openapi-typescript@latest contract/openapi.json -o contract/api-types.ts
```

Commit both. `tests/test_openapi_contract.py` regenerates the schema and compares
it against `openapi.json`, so forgetting this step fails CI with the diff instead
of reaching a client.

## Rules

- **Never hand-edit either file.** They are generated; edits will be overwritten
  and will fail the staleness test.
- **A schema diff is a review question**, not a formality: does this change break
  an existing client, and does it need a new API version?
- **Auth appears in the schema only because the dependency declares
  `HTTPBearer`.** A route that parses the `Authorization` header inline will be
  published as `open` — which is how all 122 operations were once documented as
  having no authentication at all. Use `Depends(get_current_user)`.
