## Project Vision
AcademicOS is an evidence-grounded academic intelligence system built over official CBSE corpora (curricula, NCERT textbooks, previous years' question papers, marking schemes, circulars). The system has two sub-products: **AcademicOS Web** (cloud, Flutter Web) and **AcademicOS Mobile** (offline, Flutter APK).

## Correction — measured 2026-09-21, after the sections above were written

**The "96% / 21 cells remaining" figure above counts the wrong denominator.**
It reproduces, but it tracks only one of two failure modes, and it is the
smaller one by a factor of thirty. Measured against the bank the product
actually serves:

| | Questions |
|---|---|
| Served | 3,286 |
| With an official CBSE marking scheme | 2,833 (86.2%) |
| Shipping a **completely blank** scheme (no marking points, no model answer) | **442** |

Split by why the link failed:

| Failure mode | Questions | Tracked above? |
|---|---|---|
| Paper code read, no answer row for that `q_no` | 14 | yes — the "7 + 14 cells" |
| **Paper code could not be read from the document** | **428** | no |

Root cause of the 428: three *separate* copies of the CBSE paper-code pattern
(`answer_key._PAPER_CODE`, `question_bank._CODE_HINT`, `pool._PAPER_CODE_RE`)
each required a two-or-three digit series, so none could read an English board
paper — English leads with one digit (`1/4/1`, `2/5/1`). Separately, the
marking-scheme header names the subject code immediately before the paper code
(`MS-English Core/301/1-5-1`), and matching from the left spliced the *subject*
code in, yielding a non-existent `301/1/5` and collapsing sets 1/2/3 of a paper
onto one key so each ingested set overwrote the last.

**Fixed 2026-09-21** (see `docs/superpowers/specs/2026-09-21-answer-key-variant-code-recovery-design.md`):
all three patterns now read a one-to-three digit series, `pool._paper_code_of`
delegates to the canonical `normalize_paper_code` instead of carrying a third
regex, and `301` was added to `_SUBJECT_BY_CODE`. 45 English marking schemes
re-ingested (245 answers, 33 codes).

Measured result: scheme coverage **86.2% → 89.5%**, 97 questions recovered, all
English. In the question pool paper generation actually uses, English X went
**0 → 62** keyed of 134 and English XII **0 → 41** of 93. Verified end to end:
a real paper exported to PDF, bytes read back, real marking-scheme text in place
of `(pending teacher entry)`.

### Still open after that fix

| Failure mode | Questions |
|---|---|
| No paper code in the parse tree (variant formats: `465`, `37`, `14-53`, `30(B)`, `65(B)`) | 223 |
| Code read but absent from `answer_keys.db` (marking scheme not yet ingested) | 30 |
| Code present, no answer for that `q_no` (English schemes parse only 2–15 answers each) | 92 |

Two leads, both evidenced:
1. **1,288 marking schemes sit misclassified as `doc_type == "unknown"`** in the
   parse artifacts, against only 42 classified `marking_scheme`. They cover the
   variant-code papers (`MS-Home Science/064/37`, `MS_XII_Applied
   Mathematics_241_465_2025-26`, `MS_X_Mathematics_041_30(B)_2025-26`).
2. The English value-point parser recovers few answers per scheme (2–15 against
   ~40 questions), which is why 92 questions have a matched code but no answer.

**Do not re-report the answer-key milestone as a cell count.** Report it as
measured scheme coverage over the served bank, with the shortfall named (rule Q4).

## Key Design Decisions to Respect

1. **Evidence-grounded**: Every assertion must have provenance (document_id, page_number, bounding_box)
2. **Gated acceptance**: Low-confidence material never silently enters KG
3. **Coarse > precise when wrong**: Strand-level (ENG10.1) beats leaf-level when precision < 80%
3. **Distribution-shift awareness**: CBE training ≠ board paper test; report precision as upper bound
4. **Separate inferred output**: `inferred_topics.json` separate from corpus; marked as inferred
4. **Two implementations rule**: Work in `src/academicos/` (active), NOT `backend/` (experimental)
