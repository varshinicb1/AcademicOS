## 3. Web first load (live, unauthenticated)

Measured 2026-10-07 from this machine against https://vidyuthlabs.web.app.
Transfer sizes are what the browser actually receives (`curl -sI -H
"Accept-Encoding: br"` → `content-length`). Slow 4G is Lighthouse's
throttling: 1.6 Mbps down, 150 ms RTT.

Critical-path assets (brotli):

| Asset | Bytes |
|---|---|
| `/` (index.html) | 1,322 |
| `flutter_bootstrap.a67023ed7660.js` | 3,437 |
| `main.dart.3cbc2c1c104e.js` | 1,337,419 (6,553,480 uncompressed) |
| CanvasKit `canvaskit.wasm` (gstatic, engine `5a2a6a4`) | 2,268,938 |
| Inter fonts ×4 (preloaded) | 245,485 |
| **App-start total (excl. splash icon)** | **≈ 3.68 MB** |

First meaningful paint on Slow 4G, modelled from the sizes and the wave
structure (HTML → bootstrap → main+fonts on one H2 connection → CanvasKit
on a second connection → CPU-throttled execution):

- ≈ 19–23 s. Target is < 10 s. This is consistent with the last measured
  18–21 s (pre-#127 figures quoted in `HANDOVER.md`); the font subsetting
  and preloads (#127) did not change the dominant terms: `main.dart.js`
  grew to 1.34 MB brotli and CanvasKit is 2.27 MB brotli.
- Repeat load on a warm cache: entry files and CanvasKit are cached
  (content-hashed names, long cache); measured TTFB on this connection is
  0.16 s, so repeat load is dominated by execution — comfortably under the
  3 s repeat target on this network. A school's network will vary.

Named levers (for R-A5, Phase 5, with the owner): renderer choice
(Skwasm instead of CanvasKit — smaller wasm, no separate CDN fetch),
deferred imports to cut `main.dart.js`, serving CanvasKit same-origin
from the hashed cache instead of gstatic.

Commands: `curl -s -o /dev/null -w "%{time_namelookup} %{time_connect}
%{time_appconnect} %{time_starttransfer} %{time_total} %{size_download}"`
per asset; `curl -sI -H "Accept-Encoding: br" <asset> | grep -i
content-length` for transfer sizes.

## 5. APK size

Release builds, split per ABI, against the live API
(`flutter build apk --release --split-per-abi --dart-define=ACADEMICOS_APP=<teacher|student>
--dart-define=ACADEMICOS_API="https://academicos-backend-2eskom55ta-el.a.run.app/api/v1"`):

| App | armeabi-v7a | arm64-v8a | x86_64 |
|---|---|---|---|
| Teacher | 35.3 MB | 41.3 MB | 43.5 MB |
| Student | 35.3 MB | 41.3 MB | 43.5 MB |

The student build is byte-for-byte the same size because the two apps are
one binary today: `ACADEMICOS_APP` switches mode at runtime, and the
Gradle flavors with per-app `applicationIdSuffix`, names and icons (R-B1)
do not exist yet — both dart-defines compile the same tree. Side-by-side
install is impossible until R-B1 lands.

The R-B4 bar is **under 30 MB**. Every ABI is over it today, arm64 (the
realistic phone target) by ~38%. Named as Phase 3 size work: this is one
Flutter codebase carrying the web console's School pages, the PDF stack
(pdf.dart, canvaskit-adjacent code) and offline assets; levers are
per-app tree-shaking of unused widgets/icons, deferred imports for the
admin surfaces a teacher never opens, and asset pruning. To be sized
properly in Phase 3, before Play upload.
